Tema 2 — HTML

Introdução

HTML (HyperText Markup Language) descreve o conteúdo e a estrutura das páginas Web. Um documento HTML é um ficheiro de texto com anotações que dizem ao navegador como o interpretar.

O HTML serve para:

  1. apresentar conteúdo (texto, imagens, vídeos);
  2. anotar o texto, dando-lhe estrutura (títulos, parágrafos, listas);
  3. navegar por hipertexto (hiperligações para outras páginas ou secções);
  4. embeber conteúdo externo (imagens, CSS, JavaScript, vídeo).
<!DOCTYPE html>
<html>
  <head>
    <title>Olá</title>
  </head>
  <body>
    <h1>Olá HTML 5</h1>
    <img alt="HTML5" src="logo.png">
    <a href="https://www.w3.org/TR/html5/">
      Mais informação
    </a>
  </body>
</html>

Este documento mínimo mostra um título “Olá HTML 5”, a imagem logo.png e uma hiperligação “Mais informação”. As anotações são as construções entre < e >; a opção “Ver código fonte” do navegador mostra o HTML tal como veio do servidor.

  • <a href="...">Mais informação</a> é um elemento de navegação: ao clicar, o navegador carrega outra página, identificada pelo URL do href.
  • <img src="logo.png"> é conteúdo embebido: a imagem é um ficheiro à parte, que o navegador vai buscar com outro pedido e insere na página atual. Também se embebem folhas de estilo CSS (formatação) e programas JavaScript (comportamento).

Ambos usam URLs, mas a navegação troca de página e o embeber traz conteúdo para dentro da página atual.

URLs absolutos e relativos

Um URL (Uniform Resource Locator) identifica um recurso na Internet (não só na Web: há URLs de email e FTP) e serve para o carregar.

Um URL absoluto tem três partes: protocolo (http ou https), servidor (nome ou IP, ex.: dcc.fc.up.pt) e caminho dentro do servidor (como os caminhos do Linux, ex.: /~zp/pagina.html). O separador é ://. Opcionalmente indica-se a porta depois do servidor: http://www.dcc.fc.up.pt:80/. Por omissão usa-se a 80 (HTTP) ou a 443 (HTTPS).

Um URL relativo só tem o caminho, relativo a um URL base (a diretoria da página que faz a referência). Facilita a recolocação de um conjunto de páginas (mudar o site de servidor sem mexer nas ligações internas) e é mais curto.

A página http://dcc.fc.up.pt/~zp/index.html contém <a href="logo.png">.

  1. URL base = diretoria da página atual: http://dcc.fc.up.pt/~zp/.
  2. Concatena-se o caminho relativo: http://dcc.fc.up.pt/~zp/ + logo.png.
  3. URL absoluto: http://dcc.fc.up.pt/~zp/logo.png, que é o que o navegador pede.

Se a página estiver numa subdiretoria, o URL base muda com ela:

  • página: http://dcc.fc.up.pt/~zp/galeria/index.html
  • logo.png resolve para http://dcc.fc.up.pt/~zp/galeria/logo.png

Morfologia dos elementos

Anotações e contentores

As anotações são delimitadas por < e > e começam por um nome (o vocabulário do HTML), muitas vezes mnemónica do inglês: br = BReak, hr = Horizontal Rule. Funcionam como comandos.

Uma anotação vazia (<br>, <hr>) não tem conteúdo nem fecho. Um contentor é delimitado por um par de anotações com o mesmo nome: início (<p>) e fecho, que começa por barra (</p>).

Os contentores podem ser aninhados. Uma anotação de fecho termina a última anotação aberta com esse nome (ordem de pilha).

Em <p> Este contentor tem um <b>pequeno</b> texto </p>, o </b> fecha o <b>, aberto por último, e só depois o </p> fecha o parágrafo.

Atributos

Os atributos são as “opções” de uma anotação. Só aparecem na anotação de início, cada um é uma palavra sem espaços e a ordem é irrelevante.

Atributos simples (booleanos): só o nome, ex. <input disabled>, <option selected>. Verdadeiro se presente, falso se ausente.

Pares nome-valor nome=valor, ex. <a href='http://www.up.pt/'>, <img src=casa.png width=90 height=50 alt="Casa d'avó">:

  • os valores são sempre strings (width=90 é texto que representa um número);
  • delimitam-se por aspas ou plicas, que não fazem parte do valor;
  • os delimitadores são obrigatórios se o valor tiver espaços ou outros carateres especiais (alt=HTML5 pode ir sem aspas);
  • um valor pode conter o outro delimitador: "Casa d'avó".

Entidades

Uma entidade é uma substituição de carateres (uma espécie de macro) feita durante o parsing. Começa por & e termina em ;. Serve para escrever carateres que seriam lidos como formatação, como < e >.

Entidade Carácter Significado
&amp; & o próprio &, que iniciaria uma entidade
&lt; < less than: não abre uma anotação
&gt; > greater than: não fecha uma anotação
&quot; " aspas dentro de um valor delimitado por aspas
&apos; ' plica dentro de um valor delimitado por plicas
&nbsp; espaço non-breaking space: espaço que não é colapsado
&hellip; … reticências

É com &lt; e &gt; que se mostra código HTML como texto numa página.

Texto, CDATA e comentários

O texto é tudo o que está fora de anotações e de entidades.

Uma secção CDATA, delimitada por <![CDATA[ e ]]>, inibe a formatação: tudo lá dentro é texto literal. Pode ter todos os carateres exceto ]]>, não se aninha, e serve para incluir XML embebido ou programas. É pouco usada.

Um comentário tem a forma ``:

  • as anotações lá dentro ficam inativas;
  • não pode ocorrer dentro de outras anotações;
  • a string -- não pode aparecer no texto comentado, por isso os comentários não se aninham.

Em <![CDATA[ <p> Isto é <u> tudo </u> texto </p> ]]> o conteúdo aparece tal como está escrito, com os < e >, sem precisar de &lt;/&gt;.

A declaração <!DOCTYPE html>

Aparece sempre no início e declara o tipo do documento como HTML 5. Parece uma anotação, mas não é (tem ! antes do nome), e parece um comentário, mas também não é (tem um nome em vez de --). Outras linguagens e versões têm declarações próprias: as do HTML 4 e do XHTML eram longas e remetiam para um DTD.

Estrutura do documento

Em linha e de bloco

Os contentores formam uma árvore; nas folhas estão anotações vazias (<br>, <img>) ou texto.

Cada contentor é desenhado como uma caixa retangular, com dimensão e posição, que contém as caixas dos descendentes. Há dois géneros:

  • em linha (inline): colocadas no fluxo do texto, lado a lado, sem quebra de linha;
  • de bloco (block): ocupam toda a largura disponível, com quebra de linha antes e depois.
Categoria Elemento Nome Efeito

Em linha sup, sub Superscript, Subscript expoente, índice

Elementos em linha

Fluxo do texto. O texto corre da esquerda para a direita e quebra conforme o espaço. Os carateres brancos são irrelevantes: vários espaços seguidos valem um espaço, e mudanças de linha e tabulações valem um espaço. Por isso a indentação do código fonte não tem efeito visual. Os carateres têm largura variável (|m| = 3·|i|, |a| = 2·|i|); o <code> usa carateres mono-espaçados, mas também ignora os brancos extra.

Para forçar espaços e quebras, com parcimónia: <br> dá uma quebra de linha e &nbsp; um espaço que não é colapsado.

Formatação de texto. b, i, u e s combinam-se encaixando contentores: <b><i>Negrito+Itálico</i></b>. Índices e expoentes: <sup> e <sub> deslocam o texto em relação à linha de base e reduzem-no (~75%), ex.: e = m.c<sup>2</sup> dá e = m.c². Em <b>Negrito <sup>expoente <sub>índice</sub></sup></b>, tudo fica a negrito, “expoente” sobe e, dentro dele, “índice” fica ainda mais pequeno e desce.

A âncora <a> é a base das hiperligações. Tem dois atributos, usados em alternativa:

  • name cria um alvo (um ponto endereçável na página);
  • href cria a hiperligação para um alvo. Se o alvo é um name da mesma página, o valor começa por #.

O contentor de um <a href> é o ponto ativo que se clica, e por omissão aparece a azul e sublinhado.

<a name="top"> Vai ser muiiito longo ... </a>
<a href="#top">Início</a>

Clicar em “Início” não carrega página nova: salta para o ponto top da mesma página.

Elementos de bloco

  • <hr>: régua horizontal, uma caixa achatada a toda a largura; separa mais do que um <br>.
  • <p>: parágrafo, com texto e elementos em linha; reserva espaço entre parágrafos consecutivos.
  • <h1>…<h6>: cabeçalhos, h1 o mais destacado, h6 o menos.

Listas: <ul> é itemizada (bullets) e <ol> é ordenada (números). Os itens são blocos <li>. O fecho </li> pode ser omitido (o item seguinte ou o fim da lista fecha-o), e numa <ol> o atributo value força o número do item (<li value=4> dá “4.”).

Lista descritiva <dl>, como um dicionário: cada entrada é um termo <dt> (Defined Text) e a sua definição <dd> (Definition).

<dl>
  <dt> <b>Itemizada</b>
  <dd>
    <ul>
      <li> Primeiro
      <li> Segundo
    </ul>
  <dt> <b>Ordenada</b>
  <dd>
    <ul>
      <li> Primeiro
      <li> Segundo
    </ul>
</dl>

Cada <dd> contém uma lista itemizada inteira: blocos aninham-se livremente dentro de blocos.

Imagens. <img> insere conteúdo embebido, com as dimensões do próprio ficheiro, a não ser que os atributos as mudem: src (URL da imagem), alt (texto alternativo, se a imagem não carregar, e para leitores de ecrã), width e height (em pixels).

A estrutura de topo

Um documento HTML:

  • começa pela declaração de tipo <!DOCTYPE html>;
  • tem uma única raiz, <html> (o DOCTYPE e comentários antes dela não fazem parte da árvore);
  • a raiz tem exatamente dois filhos: <head>, o cabeçalho (metadados, como o <title>; não é mostrado na área de trabalho), e <body>, o corpo (o que é mostrado).

Dentro do <body> não há estrutura rígida, mas certos elementos têm de estar dentro de outros (<li> dentro de <ul>/<ol>, <td> dentro de <tr>).

Validação

O HTML é um tipo de documento anotado: há um conjunto definido de anotações válidas, e cada uma pode ter certos atributos e conter certos tipos de anotações (eventualmente nenhum). No HTML 4 esta gramática era um DTD (Document Type Definition); o HTML5 não tem DTD, mas a ideia mantém-se.

Interoperabilidade. Os navegadores são tolerantes: mostram HTML inválido em vez de o recusar. Mas cada um pode interpretá-lo de forma diferente, e a página varia de navegador para navegador. Exemplos de HTML inválido tolerado:

  • anotações de fecho omitidas (</head>, </body>, </html>; o </li> é permitido omitir no HTML5);
  • fechos fora de ordem: <b><i> ... </b></i> em vez de <b><i> ... </i></b>;
  • valores de atributos sem aspas quando deviam ter.

Uma página que “parece funcionar” num navegador pode não estar correta. Os validadores verificam o código; o de referência é o Validador do W3C (https://validator.w3.org/), que valida páginas publicadas (pelo URL), ficheiros carregados ou texto colado.

Formulários

Os formulários permitem ao utilizador introduzir valores através de widgets que restringem ou validam o que se escreve, e submeter esses valores a um servidor.

O elemento <form> agrega widgets a submeter ao servidor. Pode ser omitido se os widgets só forem usados no cliente, e pode haver vários numa página. Atributos:

  • action: o URL do recurso que recebe os dados;
  • method: o método HTTP (get ou post).

Com method=get†, os pares nome-valor vão no URL (?Nome=Ana&Idade=20), visíveis na barra de endereços: serve para pesquisas. Com method=post, vão no corpo do pedido: para dados sensíveis ou para criar/alterar algo no servidor.

Todos os widgets têm name (a chave do par enviado) e value (o valor atual). Os dois ligados à submissão são reset (repõe os valores iniciais) e submit (envia os pares ao action).

O <input> é o widget mais versátil; o atributo type escolhe o tipo. Os tipos especializados do HTML5 só aceitam valores válidos (ex.: um mês 13 não) e mostram a estrutura esperada e seletores de ajuda (calendário, seletor de cor).

<select> agrega opções <option>. Com size=1 (omissão) é um menu suspenso; com size=n > 1 é uma lista com nn valores visíveis. <optgroup label="..."> agrupa opções com um cabeçalho. O value de uma <option> pode ser diferente do texto mostrado (mostra “XXXL”, envia 9). O fecho </option> pode ser omitido.

<textarea> serve para texto multi-linha (o <input type=text> é de uma linha). rows dá o número de linhas visíveis e cols a largura em carateres. O texto entre <textarea> e </textarea> é o valor inicial.

<form action=registar method=post>
  Nome <input name=Nome><br>
  Idade <input type=number name=Idade> <br>
  Email <input type=email name=Email> <br>
  Data de nascimento <input name=Nasce type=date>
  <input type=reset>
  <input type=submit value=Registar>
</form>
  1. action=registar method=post: os dados vão para o recurso registar do servidor atual, no corpo do pedido.
  2. <input name=Nome>: texto simples (tipo por omissão), enviado como Nome=....
  3. type=number name=Idade: só aceita números; envia Idade=....
  4. type=email name=Email: o navegador valida o formato; envia Email=....
  5. name=Nasce type=date: seletor de data; envia Nasce=... (a ordem dos atributos é irrelevante).
  6. type=reset: repõe todos os campos (aqui, vazios).
  7. type=submit value=Registar: o value é o texto do botão.

Ao clicar “Registar”, o navegador junta os pares nome=valor e envia-os por POST para registar.

Tabelas

Uma tabela organiza conteúdo em linhas e colunas, mas no HTML é uma árvore: a tabela contém linhas e cada linha contém células. As células podem ter texto, imagens ou outras tabelas.

  • <table>: a tabela;
  • <tr> (Table Row): uma linha;
  • <td> (Table Data): uma célula;
  • <th> (Table Header): célula de cabeçalho, em vez de <td>; por omissão centrada e a negrito;
  • colspan / rowspan: a célula ocupa esse número de colunas / linhas contíguas.
<table>
  <tr> <td>X</td> <td>&nbsp;</td> <td>&nbsp;</td> </tr>
  <tr> <td>O</td> <td>X</td>      <td>O</td>      </tr>
  <tr> <td>X</td> <td>O</td>      <td>&nbsp;</td> </tr>
</table>

Um jogo do galo: cada <tr> é uma linha da grelha 3×3. As células vazias levam &nbsp; para não colapsarem. Os bordos não vêm do HTML: uma tabela sem CSS não tem bordos.

<table>
  <tr>
    <th colspan=3>Dados</th>
  </tr>
  <tr>
    <th>Sexo</th> <th>Nome</th> <th>Idade</th>
  </tr>
  <tr>
    <td rowspan=2>&#9792;</td>
    <td>Sofia Costa<td>19
  </tr>
  <tr>
    <td>Joana Dias<td>20
  </tr>
</table>
  1. <th colspan=3>Dados</th> substitui as três células da primeira linha: é um título a toda a largura.
  2. A segunda linha tem os três cabeçalhos de coluna.
  3. <td rowspan=2>&#9792;</td> (o símbolo feminino) ocupa a coluna “Sexo” na terceira e na quarta linha. Por isso a quarta linha só tem duas células (Nome e Idade).
  4. Os </td> foram omitidos (<td>Sofia Costa<td>19): um <td> novo fecha o anterior, como no </li> e no </option>.

Posicionamento com tabelas. Antes do CSS, usava-se <table> como grelha invisível para posicionar texto, imagens ou outras tabelas. Hoje é má prática† (mistura dados com apresentação): o layout faz-se em CSS (Tema 4).

No HTML5 a formatação das tabelas faz-se só em CSS (o HTML4 tinha atributos de formatação nas anotações). Três elementos agrupam linhas para o CSS as formatar de forma diferente: <thead> (cabeçalho), <tbody> (corpo) e <tfoot> (rodapé, ex.: totais).

<table>
  <thead>
    <tr><th>NCD</th><th>Nome</th><th>Classificação</th></tr>
  </thead>
  <tbody>
    <tr><td>20999999</td><td>Fulano de Tal</td><td>18</td></tr>
    <tr><td>20999999</td><td>Beltrano de Qual</td><td>17</td></tr>
  </tbody>
  <tfoot>
    <tr>
      <th colspan=2>Média</th><td>13.5</td>
      <th colspan=2>Inscritos</th><td>75</td>
    </tr>
  </tfoot>
</table>

Numa pauta, o <thead> tem os nomes das colunas, o <tbody> uma linha por aluno e o <tfoot> a média e os inscritos, que o CSS pode destacar (fundo escuro, negrito).

Tema 3 — CSS: regras, seletores e padrões

Regras CSS

O CSS (Cascading Style Sheets) descreve a apresentação visual de documentos estruturados (XML, mas sobretudo HTML5). Uma folha de estilos é um conjunto de regras.

Uma regra associa valores de propriedades a elementos:

seletor { propriedade: valor; }

O seletor diz a que elementos se aplica; a declaração (entre chavetas) diz que propriedade muda e para que valor, separados por :. Ex.: H1 { font-weight: bold } põe todos os <h1> a negrito.

Os comentários são /* ... */ (não há //). Servem para documentar e para inativar temporariamente uma regra.

Agrupar seletores: separados por vírgula, recebem todas as declarações do bloco. Agrupar declarações: separadas por ponto e vírgula. É boa prática pôr ; também depois da última declaração (ver o ; como terminador, não como separador). As duas formas combinam-se: uma regra com nn seletores e mm declarações equivale a n×mn\times m pares seletor-declaração.

H1, H2, H3 {
    color:          gray;
    text-transform: capitalize;
    font-family:    arial, helvetica;
}

Esta regra vale por nove: cada um de H1, H2, H3 recebe as três declarações.

A cascata

As propriedades de um elemento podem estar dispersas por várias regras, com valores em conflito. A cascata (o C de CSS) resolve-os.

  1. Origem: as regras do autor do documento vencem as do leitor/navegador.
  2. Especificidade: na mesma origem, vence a regra mais específica.
  3. Ordem: com especificidade igual, vence a última declarada.
  4. !important: força a precedência de uma declaração, passando à frente dos três critérios anteriores.
/* author */
h3.other   { font-style: italic; }
h1, h2, h3 {
    font-family: san-serif;
    font-weight: bold;
    font-style:  normal;
}
h1 { font-size: xx-large; }
h2 { font-size: x-large;  }
h3 { font-size: large; font-style: italic; }
h2 { font-size: 110%;     }

/* user agent (navegador) */
h1, h2, h3 {
    font-family: serif;
    font-weight: 500 !important;
}

Neste exemplo, font-family, font-weight, font-style e font-size aparecem várias vezes: a cascata resolve cada propriedade em separado.

1. Origem. O navegador também define regras (valores por omissão e preferências do leitor, ex.: letra maior); o documento traz as do autor. As do autor vencem. A especificação real† tem três origens, e o !important inverte a ordem entre elas, da menor para a maior prioridade:

user agent < utilizador < autor < autor !important < utilizador !important < user agent !important

2. Especificidade. Há quatro categorias de seletores, com pesos crescentes: tipo < classe < ID < estilo em linha (style=). O peso de um seletor depende de quantos seletores de cada categoria tem, e vence o de maior peso.

A especificidade é um tuplo (b,c,d)(b, c, d):

  • bb = número de IDs (#x);
  • cc = número de classes (.x), atributos ([x]) e pseudo-classes (:hover);
  • dd = número de tipos (h1, div) e pseudo-elementos (::before).

Compara-se posição a posição: primeiro bb; só se empatar, cc; só se empatar, dd. Nunca se soma: 1 ID vence 50 classes. Um style= em linha é um quarto número a=1a = 1 à frente, que vence qualquer seletor (exceto !important).

Três regras para o mesmo <li id="menu" class="menu-item active">:

nav ul li.active   { background: yellow; }   /* A */
#menu .active      { background: orange; }   /* B */
.menu-item.active  { background: green;  }   /* C */
Seletor IDs bb Classes cc Tipos dd (b,c,d)(b,c,d)
nav ul li.active 0 1 (.active) 3 (nav, ul, li) (0,1,3)(0,1,3)
#menu .active 1 1 (.active) 0 (1,1,0)(1,1,0)
.menu-item.active 0 2 (.menu-item, .active) 0 (0,2,0)(0,2,0)

Primeira posição: B tem b=1b = 1, A e C têm b=0b = 0. B vence logo, sem olhar para cc nem dd: o fundo é laranja. C tem mais classes do que B, mas um ID pesa mais do que qualquer número de classes.

3. Ordem de declaração. Com a mesma origem e especificidade, vence a última declarada (mais abaixo na folha, ou na última folha carregada). No exemplo da cascata, h2 { font-size: x-large; } e h2 { font-size: 110%; } têm a mesma especificidade (0,0,1)(0,0,1); a segunda vem depois, por isso h2 fica com 110%. Por isso importa a ordem entre <link> e <style>† no documento.

4. !important. Escrito depois do valor (font-weight: 500 !important;), força a precedência dessa declaração, mesmo com menor especificidade ou declarada antes. Usar com parcimónia: só outro !important o sobrepõe, o que torna o CSS difícil de depurar.

Associar CSS ao HTML

  • Folha externa: um ficheiro .css só com regras, ligado no <head> com <link rel="stylesheet" href="..." type="text/css">. Reutiliza as regras entre páginas e dá consistência a um site.
  • Folha interna: regras dentro de <style> no <head>, só para essa página. Os navegadores aceitam <style> no <body>, mas não é válido.
  • Estilo local: o atributo style de um elemento, só com pares propriedade-valor, sem seletor. Formata um único elemento, ou substitui pontualmente uma regra geral (tem a maior especificidade; só um !important o vence).
<!DOCTYPE html>
<html>
<head>
  <title>Olá mundo</title>
  <link rel="stylesheet" href="style.css" type="text/css">
  <style>
     h1 { color: orange; }
  </style>
</head>
<body>
    <h1 style="font-weight: 500;">Olá mundo</h1>
</body>
</html>

  • Classe (.strong, com ponto): todos os elementos cujo atributo class contém esse nome (o 1.º e o 3.º).

Contentores genéricos: div e span

Quando nenhum elemento tem o significado certo, há dois contentores sem significado, só para pendurar um id, uma class ou um style:

<div style="background: orange;">
  Em fundo laranja e
  <span style="color: white;"> texto com cor branca </span> !!
</div>
  • div é de bloco: permite formatar a caixa inteira.
  • span é em linha: não quebra o texto; muitas propriedades (como a cor) são herdadas pelo que contém.

Combinar seletores

O atributo class aceita vários nomes, separados por espaço: em <p class="strong important"> aplicam-se as regras de .strong e de .important.

Um tipo colado a uma classe restringe a classe a esse tipo:

p.important { background: orange; }
.important  { color: red; }
<p class=important> Lorem ipsum dolor sit amet, ... </p>
<p> Donec <span class=important>cursus</span> orci ...  </p>

O <p class=important> fica vermelho e com fundo laranja; o <span class=important> só fica vermelho. Atenção ao espaço: p.important são os p com a classe important, e p .important (com espaço) são os elementos com a classe important dentro de um p (descendência).

Elementos semânticos do HTML5

Um elemento semântico é um contentor cujo nome diz o papel do conteúdo. Tal como div/span, em geral não tem formatação própria, mas só se usa quando o significado se adequa. Captura papéis recorrentes da publicação eletrónica e melhora a acessibilidade (um leitor de ecrã anuncia a navegação ao encontrar um <nav>).

  • <header>: bloco de cabeçalhos (<h1>, <img>, <a>). Pode haver vários (um da página, um por <article>), mas nunca dentro de <header>, <footer> ou <address>.
  • <nav>: links da navegação principal (listas <ul>, <li>, <a>).
  • <main>: o conteúdo mais relevante; costuma conter <article> e ter um título (<h2>).
  • <article>: um tema autónomo, que faz sentido isolado (um post, uma notícia); contém <section> ou parágrafos e tem título (<h3>).
  • <section>: uma secção de um documento; costuma haver várias num <article> ou <main>; tem título (<h4>).
  • <aside>: informação complementar, muitas vezes ao lado.
  • <footer>: fecho da página ou de um <article>; pode haver vários.

Outros elementos semânticos: sem formatação própria, <figure> (uma figura e a sua legenda) e <figcaption> (a legenda); com formatação própria, <mark> (texto destacado, fundo amarelo), <button> (botão para uma ação), <details> (informação que se expande e colapsa) e <summary> (a parte sempre visível de um <details>).

Tema 4 — CSS: propriedades e layout

Cada propriedade CSS tem um valor de omissão. Algumas são herdadas pelos descendentes (as de texto e tipo de letra); outras (caixa, posicionamento) aplicam-se só ao elemento onde são declaradas.

O modelo de caixa

Todo o elemento é uma caixa retangular, contida na caixa do progenitor, rodeada pelos irmãos, e que contém as caixas dos descendentes. width e height dão a largura e a altura do conteúdo, mas o espaço ocupado depende também das camadas à volta.

Quatro camadas, de dentro para fora:

  • content: o conteúdo, com as dimensões width/height;
  • padding: preenchimento entre o conteúdo e o bordo, transparente (mostra o fundo do elemento);
  • border: o bordo, a única camada que se desenha;
  • margin: margem até às caixas vizinhas, transparente e nunca desenhada.

O background-color pinta o content e o padding, nunca a margin.

Bordo: border-width (espessura), border-style (solid, dotted, …) e border-radius (cantos arredondados; um só canto com, por exemplo, border-top-left-radius). O bordo só aparece depois de definir border-style†: por omissão é none, e border-width com border-color sozinhos não desenham nada.

Um lado só: junta-se top, bottom, left ou right ao nome: margin-top, border-right, padding-left, border-top-style.

Uma dimensão leva sempre unidade.

Absolutas: cm, mm, in (polegadas, 1in = 2,54cm), pt (pontos, 1pt = 1/96in; não são pixels), pc (picas, 1pc = 12pt).

Relativas: % (da dimensão do progenitor), px (depende da resolução), em (do tamanho de letra do elemento), rem (do tamanho de letra da raiz html), vw e vh (percentagem da largura e da altura do viewport, a área visível da janela).

Com elementos aninhados, os em multiplicam-se† (1.5em dentro de 1.5em dá 2,25 vezes); o rem refere-se sempre à raiz e evita isso.

Largura total ocupada por:

div { width: 200px; padding: 20px;
      border-width: 5px; border-style: solid; margin: 10px; }
Camada Soma (esquerda + direita) Largura acumulada
content width: 200px 200px
+ padding 20 + 20 240px (limite interior do bordo)
+ border 5 + 5 250px (largura visível)
+ margin 10 + 10 270px (espaço reservado no layout)

padding, border e margin sem lado valem para os quatro lados, por isso somam-se duas vezes. A altura calcula-se da mesma forma, com os lados de cima e de baixo. width/height são só o conteúdo: é o comportamento por omissão, box-sizing: content-box†. Com box-sizing: border-box, width passa a ser a largura até ao bordo (o conteúdo encolhe para caber o padding e o border nos 200px).

Cor, texto e tipo de letra

Propriedades coloríveis: color (o que é desenhado, tipicamente o texto), background-color (fundo) e border-color (bordo).

Uma cor escreve-se por nome (red), em RGB, em hexadecimal (#FF0000) ou em função (rgb(255,0,0)), ou em HSL (Hue Saturation Lightness: matiz, saturação, luminosidade; hsl(0,100%,50%) é vermelho). Em HSL é fácil escurecer uma cor à mão†: baixa-se só a luminosidade. RGB e HSL aceitam um canal alpha de opacidade: rgba(255,0,0,0.5), hsla(0,100%,50%,0.5).

A propriedade opacity (de 0, transparente, a 1, opaco) aplica-se ao elemento inteiro, com conteúdo e descendentes. Um rgba(..., 0.5) no background-color só torna o fundo transparente†; o texto fica opaco.

  • word-spacing / letter-spacing: espaço extra entre palavras / letras (comprimento, ex. 3mm, ou normal).
  • text-align (em blocos): left (omissão), right, center, justify (todas as linhas à largura toda, exceto a última).
  • vertical-align (em elementos em linha, posição em relação à linha de texto): baseline, sub, super, top, text-top, middle, bottom, text-bottom, ou uma distância/percentagem (positiva sobe, negativa desce).
  • text-decoration: underline, overline, line-through (rasurado), blink (obsoleto), none (tira o sublinhado dos links).
  • line-height: altura de cada linha; normal, um fator (1.5 = 1,5 vezes o tamanho de letra), uma percentagem ou um comprimento (15px).
  • font-family: uma família genérica (serif, sans-serif, cursive, fantasy, monospace) ou específica (times, arial). Normalmente uma lista†, da preferida para a genérica: font-family: "Helvetica", Arial, sans-serif; (usa a primeira que existir).
  • font-style: normal, italic (a versão itálica desenhada para a fonte) ou oblique (inclinação gerada pelo navegador).
  • font-weight: normal, bold, bolder, lighter, ou 100 a 900 (400 = normal, 700 = bold).
  • font-size: xx-small, x-small, small, large, x-large, xx-large; uma percentagem (do tamanho do progenitor); ou um comprimento (24pt).
  • font-variant: normal ou small-caps (as minúsculas passam a maiúsculas pequenas, “versaletes”).

Posicionamento clássico

O posicionamento do CSS1/CSS2: flutuar, classificação e dimensões, coordenadas e referenciais, sobreposição, transbordo e centrar.

float: left / right tira o elemento do fluxo e faz-o flutuar para esse lado, com o resto do conteúdo a correr à volta. Foi pensado para imagens e tabelas, que são blocos e ocupariam a largura toda.

Vários elementos seguidos com float: left ficam lado a lado: é assim que se fazem colunas com divs. Com left o primeiro fica mais à esquerda; com right o primeiro fica mais à direita. Podem misturar-se: os left acumulam da esquerda, os right da direita.

Um elemento não flutuante a seguir pode sobrepor-se aos flutuantes. A propriedade clear (left, right, both) obriga-o a começar abaixo dos flutuantes desse lado. É comum pôr um div vazio com clear: both depois do último flutuante.

<div style="float: left; width: 45%;"> Coluna esquerda... </div>
<div style="float: left; width: 45%;"> Coluna direita... </div>

Duas colunas: o segundo div encaixa à direita do primeiro em vez de ir para baixo.

display diz como o elemento entra no fluxo, e daí como se controlam as dimensões:

  • inline: segue o fluxo do texto, lado a lado; as dimensões são as do conteúdo (width/height são ignorados);
  • block: ocupa a largura disponível e quebra a linha antes e depois; respeita width/height;
  • inline-block: posiciona-se como inline (lado a lado) e dimensiona-se como block (respeita width/height). Faz colunas sem float.

Outros valores imitam elementos HTML: table, table-row, table-cell (como <table>, <tr>, <td>), list-item (como <li>), e os do CSS3 flex, inline-flex, grid, inline-grid.

Três divs com width: 100px; height: 300px;: com block ficam empilhados (mesmo com 100px de largura); com inline ficam lado a lado, mas com o tamanho do conteúdo; com inline-block ficam três colunas de 100×300px lado a lado.

Esconder um elemento: display: none remove-o da formatação (as dimensões ficam nulas e o espaço é libertado; é o habitual para esconder com JavaScript, ex. diálogos); visibility: hidden torna-o invisível mas mantém o espaço (nada “salta”).

Coordenadas e referenciais

Um elemento posicionado (position diferente de static) desloca-se com top, right, bottom e left: a distância entre cada lado da caixa e o mesmo lado do referencial. Não é preciso dar as quatro (top e left chegam). O referencial depende de position:

position Referencial de top/right/bottom/left Mantém o espaço?
static nenhum: as coordenadas são ignoradas sim (é o fluxo normal)
relative a própria posição estática sim
absolute o primeiro antepassado posicionado (ou o documento) não
fixed a janela do navegador (não se mexe com o scroll) não
sticky relative enquanto visível; depois fixed no contentor com scroll sim
  • static (omissão): posição dada pelo display e pela ordem no documento; top/right/bottom/left são ignorados.
  • relative: o elemento mantém o espaço no fluxo e é deslocado a partir da sua posição estática. É o que implementa o vertical-align: sub/super.
  • absolute: sai do fluxo (o espaço não é mantido). Referencial: o primeiro antepassado posicionado (com position diferente de static); se não houver, o documento.
  • fixed: sai do fluxo; o referencial é a janela (viewport), por isso não se mexe com o scroll.
  • sticky: comporta-se como relative enquanto a sua posição está visível no contentor; quando o scroll a tiraria da vista, passa a fixed em relação ao contentor com scroll, e fica “colado” a essa borda (útil em cabeçalhos de secções e tabelas).

Para usar um progenitor como referencial de um descendente absolute, dá-se-lhe position: relative sem top/left†: fica posicionado sem se mexer.

Sobreposição. z-index dá a cada elemento posicionado um nível numa pilha: mais baixo fica por baixo. Só funciona em elementos posicionados; num static é ignorado.

Transbordar. Quando o conteúdo excede a caixa, overflow decide: visible (omissão; sai da caixa), hidden (cortado), scroll (barra de deslocamento sempre visível) ou auto (barra só se for preciso).

Centrar

Texto numa caixa de 200×100px:

div.botao {
  width: 200px; height: 100px;
  text-align: center;   /* horizontal */
  line-height: 100px;   /* vertical   */
}

Uma linha de texto fica centrada na vertical dentro da sua altura de linha. Com line-height igual à height da caixa, o texto fica a meio da caixa; com valores diferentes, ficaria acima ou abaixo.

Um bloco de 100×100px no contentor:

div.botao {
  width: 100px; height: 100px;
  margin: auto;        /* 1: centra na horizontal         */
  position: relative;  /* 2: posicionado, para usar top   */
  top: 50%;            /* 3: desce 50% da altura do CONTENTOR */
  margin-top: -50px;   /* 4: sobe metade da altura do botão */
}
  1. margin: auto reparte a margem esquerda e direita por igual.
  2. position: relative torna-o posicionado, para o top ter efeito.
  3. top: 50% põe o topo do botão a meio do contentor: o botão fica meio botão abaixo do centro.
  4. margin-top: -50px sobe metade da altura do próprio botão (100/2 = 50px): o centro do botão fica a meio do contentor.

Flexbox

O flexbox posiciona em fluxo, com ideias dos toolkits gráficos (preencher espaço, quebrar, alinhar). Há dois papéis: o contentor (display: flex) e os itens (os seus filhos diretos). Os itens dispõem-se ao longo do eixo principal (direção de flex-direction); o eixo transversal é o perpendicular.

Com flex-direction: row (omissão) o eixo principal é horizontal; com column é vertical†. Por isso justify-content (eixo principal) distribui na horizontal com row e na vertical com column, e align-items (eixo transversal) ao contrário.

Contentor Valores
display flex (o contentor é um bloco), inline-flex (em linha)
flex-direction row (esq.→dir., omissão), row-reverse, column (cima→baixo), column-reverse
flex-wrap nowrap (omissão: os itens encolhem para caber numa linha), wrap (quebra para a linha seguinte), wrap-reverse (para a anterior)
flex-flow atalho: direção + quebra, ex. column-reverse wrap
justify-content distribuição no eixo principal
align-items alinhamento de cada item no eixo transversal
align-content distribuição das linhas no eixo transversal

O prefixo flex- aparece quando já existe uma propriedade genérica com o mesmo nome.

Com row e três itens, justify-content:

  • flex-start: itens encostados ao início (esquerda), espaço livre no fim;
  • flex-end: encostados ao fim (direita);
  • center: agrupados no centro, espaço igual antes e depois;
  • space-between: o primeiro no início, o último no fim, o espaço livre entre os itens em partes iguais (nada nas pontas);
  • space-around: cada item recebe a mesma margem dos dois lados; entre itens o espaço fica o dobro do das pontas.

align-items (com row, eixo transversal vertical):

  • stretch (omissão): os itens esticam à altura do contentor (se não tiverem height própria);
  • flex-start / flex-end: encostados ao topo / fundo;
  • center: centrados na vertical;
  • baseline: alinhados pela linha de base do texto (útil com tamanhos de letra diferentes).

align-content só atua com várias linhas (flex-wrap: wrap e altura suficiente): distribui as linhas inteiras no eixo transversal, e aceita também space-around.

flex-basis tamanho base no eixo principal, antes de crescer/encolher; auto = tamanho do conteúdo; tem prioridade sobre width (row) ou height (column)

flex-shrink capacidade de encolher se as bases não couberem; 0 não encolhe, 1 omissão, n encolhe nn vezes mais

flex-grow. O espaço livre reparte-se proporcionalmente:

  • três itens com flex-grow: 1: três partes iguais;
  • itens com 1, 2 e 3: 1+2+3=61+2+3 = 6 partes; o primeiro recebe 1/6 do espaço livre, o segundo 2/6, o terceiro 3/6.

Com os itens a crescer não sobra espaço livre, e justify-content deixa de ter efeito.

flex-shrink. Bases de 100px, 200px e 300px com flex-shrink 1, 2 e 3: se o conjunto não couber, o terceiro perde proporcionalmente mais largura do que o primeiro.

CSS Grid

O CSS Grid posiciona em duas dimensões: uma grelha de linhas e colunas (o flexbox é uma dimensão). Dois papéis: o contentor (display: grid) e os itens (filhos diretos, colocados nas células).

As fronteiras entre células são as linhas de grelha, numeradas a partir de 1: 3 colunas têm 4 linhas de grelha verticais.

Contentor Efeito
display grid (bloco) ou inline-grid (em linha)
grid-template-columns, grid-template-rows número e dimensão das colunas/linhas, uma por valor
row-gap, column-gap “corredor” entre linhas / colunas (não nas bordas); comprimento ou normal
grid-auto-flow ordem de colocação automática: row (linha a linha, omissão) ou column
grid-auto-rows, grid-auto-columns dimensão das linhas/colunas implícitas
grid-template, gap, grid atalhos: modelos; separações; tudo

Em grid-template-columns: 100px 40% auto; há três colunas: 100px, 40% do contentor, e o resto. Cada valor pode ser um comprimento, none (omissão: sem modelo, as colunas criam-se conforme preciso), auto (pelo conteúdo), max-content / min-content (o maior / menor elemento), initial / inherit.

As linhas/colunas implícitas são as criadas quando há mais itens do que células no modelo†. Com grid-template-rows: auto auto; e itens que chegam a uma terceira linha, a altura dessa linha vem de grid-auto-rows, não do modelo. Aceita comprimento, auto (omissão), max-content, min-content.

Um item posiciona-se pelos números das linhas de grelha (as fronteiras, não as células): grid-row-start, grid-row-end, grid-column-start, grid-column-end. grid-row-start: 2 com grid-column-start: 2 põe o item na célula da 2.ª linha e 2.ª coluna.

Expandir: span n ocupa nn células: grid-row-start: span 3 dá 3 linhas de altura, grid-column-start: span 2 duas colunas de largura.

Atalhos: grid-row (início/fim de linha) e grid-column (de coluna); grid-row: span 3 é o mesmo que grid-row-start: span 3.

Tema 5 — JavaScript: a linguagem

Executar código e mostrar resultados

O JavaScript entra no HTML em elementos <script>, no body ou no head. A posição decide quando corre:

  • no body, corre durante a formatação, no ponto em que aparece (o que escrever fica ali, no meio do HTML);
  • no head, corre antes de o corpo ser formatado;
  • mais tarde, em reação a eventos (event handlers), ex.: o atributo onclick="..." corre JavaScript quando o elemento é clicado.
  1. document.write(x) / document.writeln(x) escrevem na própria formatação da página (o writeln junta \n). As anotações HTML no texto (<h3>Olá</h3>) são formatadas.
  2. alert(x) mostra uma caixa de diálogo, tipicamente em resposta a eventos. Da mesma família: prompt(mensagem) pede texto e devolve a string escrita (ou null se cancelar), e confirm(mensagem) pergunta OK/Cancelar e devolve um booleano. Nenhuma das três formata HTML.
  3. console.log(x) escreve na consola do navegador (ferramentas de programador, invisível ao utilizador): serve para depurar. Na consola também se executam comandos interativamente.

Sintaxe básica

Tipos primitivos: Number (123; inteiros e decimais não se distinguem), String ("Olá") e Boolean (true/false).

As expressões são como em Java (operadores, precedências, associatividades). Comentários // e /* */, blocos { }, e instruções separadas por ;, que pode ser omitido (ver ASI abaixo).

Variáveis: a primeira atribuição cria uma variável global implícita, mesmo dentro de uma função (evitar). Devem ser declaradas:

  • const: não pode ser reatribuída; usar sempre que possível;
  • let: âmbito do bloco { } onde é declarada;
  • var: âmbito da função (ou global); evitar.

Podem ser inicializadas na declaração, e o tipo é dinâmico: a mesma variável pode guardar valores de tipos diferentes.

document.writeln(1 + 1);        // 2
document.writeln("1" + "1");    // "11"
document.writeln(1 && 1);       // 1
document.writeln(1 && true);    // true
document.writeln(1 == "1");     // true
document.writeln(1 === "1");    // false
  • 1 + 1: dois Number, soma: 2.
  • "1" + "1": com uma String, o + concatena: "11".
  • 1 && 1: o && não converte para booleano. a && b devolve a se a for falsy (sem avaliar b), senão devolve b†. 1 é truthy, logo devolve o segundo operando, 1.
  • 1 && true: pela mesma regra, devolve true.
  • 1 == "1": igualdade fraca, converte "1" para 1: true.
  • 1 === "1": igualdade estrita, tipos diferentes: false.

O || é simétrico†: a || b devolve a se for truthy, senão b. Dá valores por omissão: nome = nomeDado || "Anónimo".

x = 1;            // sem declaração: global implícita
const y = 2;
let   z;          // undefined
var   w;          // undefined
z = 3;
w = 4;
console.log(x + y + z + w);   // 1+2+3+4 = 10

Em { let x = 1; let y = 2; { let x = 3; } }, o x = 3 é outra variável, que só existe no bloco interior; ao sair, o x de fora continua 1.

Inserção automática de ; (ASI)

O motor infere o fim de uma instrução pela mudança de linha, mas só quando a linha seguinte tornaria a instrução inválida.

const a = 1
const b = 2
const c = a + b
(a + b).toString()

Lança TypeError: b is not a function. A linha 4 começa por (, e a + b (a + b).toString() é válido (uma chamada de função), por isso não se insere ; e o motor lê:

const c = a + b(a + b).toString()

b é o número 2, que não é uma função: erro.

O ; é inserido quando: a linha seguinte tornaria a instrução inválida; a linha seguinte começa por {; a linha tem só return, break, throw ou continue (o ; vai logo a seguir, e uma expressão na linha seguinte a um return é ignorada); ou no fim do ficheiro. Boa prática: usar sempre ; como terminador.

Controlo de fluxo e funções

O controlo de fluxo é como em Java: if/else, while/do, switch/case/break, for/break/continue. As variáveis de controlo dos ciclos devem ser let. Há ainda o ciclo estendido for (variável in objeto) (ver “Objetos e arrays”).

for (let x = 1; x < 6; x++) {
   document.write(x + " é ");
   if (x % 2 == 0) {
     document.writeln("par");
   } else {
     document.writeln("ímpar");
   }
}

Escreve 1 é ímpar, 2 é par, 3 é ímpar, 4 é par, 5 é ímpar; com x = 6 a condição falha e o ciclo acaba.

Declaração: function nome(parâmetros) { definição }, sem ; (é uma declaração, não uma instrução). Os parâmetros não têm tipo. A definição pode ter return, cujo valor fica para quem invoca.

Invocação: nome(argumentos). Os argumentos atribuem-se por posição aos parâmetros, avalia-se a definição, e o valor de retorno substitui a expressão de invocação. Ex.: em soma(2, 3) com return a + b, a = 2, b = 3, e soma(2, 3) vale 5.

Âmbito de variáveis

Uma variável é local à função onde é declarada, ou global. Cada função cria um novo âmbito, e as locais escondem (shadowing) as globais com o mesmo nome. O var ignora blocos (o seu âmbito é a função); let/const respeitam o bloco.

function testarAmbito() {
  var a = "função";
  let b = "função-let";
  if (true) {
    var a = "bloco";      // a MESMA 'a' (var é de função)
    let b = "bloco-let";  // uma 'b' NOVA (let é de bloco)
    console.log("dentro do bloco:", a, b);
  }
  console.log("fora do bloco:", a, b);
}
testarAmbito();
  1. var a = "função": a (âmbito de função) vale "função".
  2. let b = "função-let": b do corpo da função.
  3. Entra no if: novo âmbito de bloco.
  4. var a = "bloco": o var ignora o bloco, por isso reatribui a mesma a, que passa a "bloco" em toda a função.
  5. let b = "bloco-let": cria uma b nova, só do bloco, que esconde a de fora.
  6. Escreve dentro do bloco: bloco bloco-let.
  7. Sai do bloco: a b do bloco desaparece; a de fora nunca mudou.
  8. Escreve fora do bloco: bloco função-let.

É por isto que se evita o var: uma variável de ciclo “vaza” para fora do if/for/while.

Elevação (hoisting)

As declarações var e function são elevadas para o início do seu âmbito: é como se estivessem lá escritas, mas a inicialização fica onde está. Pode-se usar uma variável ou função antes da linha da declaração, mas a declaração tem de existir algures.

document.writeln(x);
document.writeln(getX());
x = 1;
document.writeln(x);

function getX() {
    var x = 2;
    return x;
}

var x;

O var x sobe sem valor; a function getX sobe inteira (as declarações de função sobem completas). O motor vê:

var x;                                     // undefined
function getX() { var x = 2; return x; }
document.writeln(x);
document.writeln(getX());
x = 1;
document.writeln(x);
  1. x existe mas não tem valor: escreve undefined.
  2. getX() usa o seu x local (var x = 2, outro âmbito): escreve 2.
  3. x = 1 atribui ao x global.
  4. Escreve 1.

Resultado: undefined, 2, 1. Sem var x em lado nenhum, a primeira leitura daria ReferenceError. let/const† também são elevadas, mas usá-las antes da linha da declaração dá erro (temporal dead zone).

Funções anónimas

Uma função pode ser uma expressão, sem nome: atribui-se a uma variável ou invoca-se logo (IIFE, Immediately Invoked Function Expression), o que também cria um âmbito próprio para variáveis temporárias. Há ainda a sintaxe seta, =>.

let somar = function(a, b) { return a + b; };
document.writeln(somar(2, 3));                              // 5
document.writeln((function(a, b) { return a + b; })(2, 3)); // 5 (IIFE)
document.writeln(((a, b) => a + b)(2, 3));                  // 5 (seta)

Na seta, um corpo que é uma só expressão é devolvido sem return nem chavetas. Os parêntesis à volta da função† fazem dela uma expressão; sem eles, function seria lida como o início de uma declaração e a chamada a seguir daria erro de sintaxe.

Modo estrito

A diretiva "use strict" (uma string, que motores antigos ignoram) torna a linguagem mais estrita. Global, no início do ficheiro, ou local, no início de uma função. Proíbe: usar variáveis e funções sem as declarar (x = 1 dá erro); remover (delete) variáveis e funções; a construção with; e usar como identificadores palavras reservadas para versões futuras.

Objetos e arrays

Os objetos criam-se com new. Há classes predefinidas, cada uma com métodos (hoje.getFullYear()) e propriedades ('ola mundo'.length): String, Date, RegExp, Object. As aspas de 'ola mundo' são açúcar sintático para new String('ola mundo').

  • undefined: variável ou propriedade nunca atribuída, ou propriedade que não existe.
  • null: objeto explicitamente marcado como inexistente (é o programador que o atribui).

null == undefined é true (regra especial), mas null === undefined é false. Um objeto real nunca é == a null.

Propriedades criam-se dinamicamente ao inicializá-las, sem declaração, e só existem no objeto onde foram criadas. Ler uma que não existe dá undefined. O operador in diz se ela existe.

Arrays são objetos da classe Array; a dimensão é opcional na construção. Acedem-se com [ ], e índices para lá da dimensão fazem o array crescer. Índices não atribuídos dão undefined.

Propriedade = índice: obj.nome, obj['nome'] e obj[prop] (com prop = 'nome') são a mesma propriedade. Com . a chave é um literal com as regras dos nomes de variáveis; com [ ] é uma expressão qualquer, convertida para string.

delete remove uma propriedade ou índice (delete obj['nome'], delete obj.estado); depois disso dá undefined e in dá false. Num array, delete deixa um buraco† (o length não muda); para tirar e fechar o buraco usa-se array.splice(indice, 1).

const obj1 = new Object();
const obj2 = new Object();
obj1.nome = 'Objeto um';
document.writeln(obj1.nome);       // Objeto um
document.writeln(obj2.nome);       // undefined
document.writeln('nome' in obj1);  // true
document.writeln('nome' in obj2);  // false

const array = new Array(2);
array[0] = 'Início';
array[1] = 123;
array[3] = true;                   // salta o 2: o array cresce
for (let i = 0; i < 5; i++)
  document.writeln(i + ':' + array[i]);

O ciclo escreve 0:Início, 1:123, 2:undefined (nunca atribuído), 3:true e 4:undefined (para lá do que foi atribuído).

Igualdade: == e ===

O === só dá true com o mesmo tipo e o mesmo valor; o == converte um dos lados primeiro.

Expressão == === Porquê
1 e "1" true false "1" convertida para 1
null e undefined true false regra especial
0 e "" true false "" convertida para 0
NaN e NaN false false NaN nunca é igual a nada, nem a si próprio

NaN (Not a Number, ex. 0/0) testa-se com Number.isNaN(x)†, nunca com x == NaN.

Iteração

  • for (variável in objeto) percorre as chaves. A variável deve ser declarada com let (ou já existir).
  • for (variável of iterável) percorre os valores de uma coleção iterável (arrays, Maps, strings).

Num array, in dá os índices e of os valores.

const pessoa = new Object();
pessoa.nome  = 'Ninguém';
pessoa.idade = 99;
pessoa.ativo = true;
for (let campo in pessoa)
   document.writeln(campo + ' = ' + pessoa[campo]);
// nome = Ninguém / idade = 99 / ativo = true

const numeros = [null, 'primeiro', 'segundo', 'terceiro'];
for (let indice in numeros) document.writeln(indice);  // 0 1 2 3
for (let valor of numeros) document.writeln(valor);    // null primeiro segundo terceiro

Os arrays têm também métodos de iteração†, que recebem uma função:

const numeros = [1, 2, 3, 4];
numeros.forEach(n => document.writeln(n * 10));        // 10 20 30 40, não devolve nada
const dobros = numeros.map(n => n * 2);                // [2,4,6,8]
const pares  = numeros.filter(n => n % 2 == 0);        // [2,4]
const soma   = numeros.reduce((acc, n) => acc + n, 0); // 0+1+2+3+4 = 10

forEach(f) chama f(valor, indice, array) por elemento; map(f) faz um array novo com os resultados; filter(f) um array novo com os elementos em que f dá truthy; reduce(f, inicial) acumula tudo num valor. Nenhum altera o array original.

Map

A classe Map cria arrays associativos previsíveis (as chaves de um objeto podem incluir, por exemplo, métodos herdados).

const pessoa = new Map();
pessoa.set('nome', 'Ninguém');
pessoa.set('idade', 99);
pessoa.set('ativo', true);
for (let dado of pessoa)
    document.writeln(dado[0] + " = " + dado[1] + "\n" + pessoa.get(dado[0]));

O for-of dá, em cada volta, um par [chave, valor]; get(chave) lê um valor. Escreve nome = Ninguém, Ninguém, idade = 99, 99, ativo = true, true. O for-in não funciona em Maps.

Map Objeto
Chaves qualquer valor (objetos, funções) só tipos simples (strings, símbolos)
Ordem a de inserção, sempre “lexicográfica”†: na prática, chaves que parecem inteiros primeiro (por ordem numérica), depois as outras pela ordem de inserção
Tipo um Map é um objeto um objeto não é um Map (não tem set/get)

Notação de objetos, construção e desconstrução

Objetos escrevem-se { nome: valor, ... } e arrays [ valor, ... ], e um valor estruturado segue o mesmo formato:

const pessoa = {
    nome: 'Fulano de tal',
    idade: 99,
    morada: { endereco: 'Rua Nova', codPostal: '4000-001 PORTO' },
    hobbies: ['sky diving', 'graffiti']
};
document.writeln(pessoa.morada.endereco);   // Rua Nova
document.writeln(pessoa.hobbies[1]);        // graffiti

Construção abreviada: se as variáveis têm o nome das propriedades, { nome, idade, morada } é o mesmo que { nome: nome, idade: idade, morada: morada }.

A desconstrução (destructuring) faz o inverso: um “molde” à esquerda de uma atribuição extrai variáveis de uma estrutura.

let hobbies = ['sky diving', 'graffiti'];
let [primeiro, segundo] = hobbies;
console.log(primeiro, segundo);              // sky diving graffiti
[segundo, primeiro] = [primeiro, segundo];   // troca, SEM let
console.log(primeiro, segundo);              // graffiti sky diving
  1. Nos arrays emparelha-se pela posição: primeiro = hobbies[0], segundo = hobbies[1].
  2. Na troca, avalia-se primeiro o lado direito com os valores atuais, ['sky diving', 'graffiti'], e depois desconstrói-se: segundo fica 'sky diving' e primeiro fica 'graffiti'. Leva sem let: let de novo daria SyntaxError (variável já declarada).
const pessoa = { nome: 'Fulano de tal', idade: 99,
    morada: { endereco: 'Rua Nova', codPostal: '4000-001 Porto' } };
let { nome, idade, morada } = pessoa;
let { nome: name, morada: { endereco: street, codPostal: zip } } = pessoa;
console.log(name, street, zip);   // Fulano de tal Rua Nova 4000-001 Porto

Nos objetos emparelha-se pelo nome. nome: name renomeia (cria name com o valor de pessoa.nome), e o molde pode aninhar-se para descer em morada. Propriedades desnecessárias omitem-se.

Programação orientada a objetos

O ES6 (ECMAScript 2015) trouxe a sintaxe class, para estruturação (hierarquia de componentes), reutilização (herança) e encapsulação: definir classes, instanciar objetos, associar campos e métodos, e estender classes.

Mas class é açúcar sintático sobre os objetos e protótipos que já existiam: as classes são opcionais, não há encapsulação real (tudo o que está em this é acessível de fora), e só se reutilizam definições, não declarações (interfaces).

Um objeto sem classe escreve-se em notação de objetos, com métodos como propriedades-função. Serve para objetos únicos:

let joao = {
    nome: "João",
    nasce: new Date(1999, 3 - 1, 15),   // meses contam de 0: 2 = março
    hobbies: ["programação", "mergulho"],
    idade: function() {
        var agora = new Date();
        var msAno = 1000 * 60 * 60 * 24 * 365.25;
        return Math.floor((agora.getTime() - this.nasce.getTime()) / msAno);
    }
};

Em joao.idade(), this é o próprio joao.

  • class Nome { ... } define uma classe.
  • O método constructor(...) inicializa cada nova instância.
  • Nos métodos, this é o objeto corrente.
  • Os campos são propriedades atribuídas a this (normalmente no constructor); não há declaração separada de campos.
  • new Nome(argumentos) cria uma instância e passa os argumentos ao constructor.
  • Métodos são funções da classe; usam campos e outros métodos através de this e podem devolver um valor.
class Pessoa {
    constructor(nome, ano, mes, dia) {
        this.nome  = nome;
        this.nasce = new Date(ano, mes - 1, dia);
    }
    saudacao(outro) {
        return 'Olá ' + this.nome + ', eu sou o ' + outro.nome;
    }
    saudar(outro) {
        console.log(this.saudacao(outro));
    }
}
let joao  = new Pessoa("João", 1999, 3, 15);
let maria = new Pessoa("Maria", 2000, 5, 21);
joao.saudar(maria);
  1. new Pessoa("João", 1999, 3, 15) cria um objeto e corre o constructor com this = esse objeto: this.nome = "João", this.nasce = 15 de março de 1999 (mes - 1 = 2, porque o Date conta os meses a partir de 0). O mesmo para maria.
  2. joao.saudar(maria): this = joao, outro = maria.
  3. this.saudacao(outro) mantém this = joao. Devolve 'Olá ' + joao.nome + ', eu sou o ' + maria.nome, ou seja, "Olá João, eu sou o Maria".
  4. saudar escreve isso na consola.

Ler um dado de outra instância (outro.nome) é uma troca de mensagens entre objetos, a ideia central da orientação a objetos.

Acessores e membros estáticos

Os acessores get/set são métodos que medeiam o acesso a uma propriedade, mas usam-se como a propriedade, sem parêntesis.

const MS_ANO = 1000 * 60 * 60 * 24 * 365.25;
class Pessoa { // ...
  get idade() {
      let agora = new Date();
      return Math.floor((agora.getTime() - this.nasce.getTime()) / MS_ANO);
  }
  set idade(anos) {
      let agora = new Date();
      this.nasce = new Date(agora.getTime() - anos * MS_ANO);
  }
}
joao.idade = 99;                                            // SET
document.writeln("O " + joao.nome + " tem " + joao.idade);  // GET

joao.idade = 99 não cria a propriedade idade: chama set idade(99), que recalcula this.nasce para quem tem 99 anos hoje. Ler joao.idade chama get idade(), que calcula a idade a partir de this.nasce: dá 99. Um acessor guarda o estado noutro campo (nasce): se o get idade fizesse this.idade = ..., chamaria o set, que podia chamar o get, num ciclo infinito.

Um método static pertence à classe, não a uma instância: não tem this e invoca-se com o nome da classe.

class Pessoa {
    static duracao(inicio, fim) {
        return (fim.getTime() - inicio.getTime()) / MS_ANO;
    }
    idade() {
        return Pessoa.duracao(new Date(), this.nasce);
    }
}

Em joao.idade(), this = joao; Pessoa.duracao(...) corre só com os parâmetros inicio e fim, sem this.

Herança

class B extends A cria uma subclasse que herda tudo de A, pode redefinir métodos (override) e acrescentar novos. super dá acesso às definições da superclasse imediata.

class Aluno extends Pessoa {
  saudacao(outro) {
     return 'Oi ' + this.nome + ', tudo em cima? Aqui ' + outro.nome + '!';
  }
  saudarCareta(outro) {
     console.log(super.saudacao(outro));
  }
}
let marco = new Aluno("Marco", 2001, 1, 13);
marco.saudar(joao);        // Oi Marco, tudo em cima? Aqui João!
marco.saudarCareta(joao);  // Olá Marco, eu sou o João
  1. Aluno não tem constructor: usa o de Pessoa.
  2. marco.saudar(joao): saudar é herdado de Pessoa e chama this.saudacao(outro). Como this = marco é um Aluno, corre a versão redefinida em Aluno: "Oi Marco, tudo em cima? Aqui João!".
  3. marco.saudarCareta(joao): super.saudacao(outro) salta a redefinição e corre a de Pessoa: "Olá Marco, eu sou o João".
class Pessoa {
  constructor(nome) { this.nome = nome; }
  saudacao() { return `Olá, sou ${this.nome}`; }
}
class Aluno extends Pessoa {
  constructor(nome, curso) {
    super(nome);                 // constructor de Pessoa
    this.curso = curso;
  }
  saudacao() { return `${super.saudacao()} e estudo ${this.curso}`; }
}
class Finalista extends Aluno {
  constructor(nome, curso, anoFinal) {
    super(nome, curso);          // constructor de Aluno
    this.anoFinal = anoFinal;
  }
  saudacao() { return `${super.saudacao()} (ano final: ${this.anoFinal})`; }
}
let f = new Finalista("Marco", "Eng. Informática", 2026);

Construção:

  1. new Finalista(...) cria um objeto f e corre o constructor de Finalista com this = f.
  2. super(nome, curso) corre o constructor de Aluno com o mesmo this = f.
  3. Lá dentro, super(nome) corre o de Pessoa: f.nome = "Marco".
  4. De volta a Aluno: f.curso = "Eng. Informática".
  5. De volta a Finalista: f.anoFinal = 2026.

f é um objeto com os três campos.

f.saudacao():

  1. A procura começa em Finalista, que define saudacao. Aí this = f (o objeto à esquerda do ponto, em qualquer nível).
  2. super.saudacao() em Finalista chama a versão de Aluno, ainda com this = f.
  3. super.saudacao() em Aluno chama a de Pessoa: devolve "Olá, sou Marco".
  4. Aluno junta " e estudo Eng. Informática".
  5. Finalista junta " (ano final: 2026)":
Olá, sou Marco e estudo Eng. Informática (ano final: 2026)

O this é sempre o objeto que recebeu a chamada. O super é a classe acima daquela onde está escrito: em Finalista vai a Aluno, em Aluno vai a Pessoa.

Por baixo†, cada objeto aponta (__proto__) para o .prototype da sua classe, e cada .prototype para o da superclasse, até Object.prototype e null. Procurar um método é subir esta cadeia de protótipos até à primeira definição.

Callbacks e classes anónimas

Uma função pode passar-se como argumento: setTimeout(funcao, ms) chama funcao ao fim de ms milissegundos.

class Pessoa { // ...
   alerta(quando, mensagem) {
       let callback = () => this.alertar(mensagem);
       let millisecs = (quando.getTime() - (new Date()).getTime());
       setTimeout(callback, millisecs);
   }
   alertar(mensagem) {
       alert("Olá " + this.nome + "\nSão horas de " + mensagem);
   }
}

O callback tem de ser uma seta†. Uma função normal recebe o this de como é invocada, e o setTimeout chama-a solta (sem objeto à esquerda do ponto): o this seria undefined (modo estrito) ou o objeto global. A seta não tem this próprio: usa o do sítio onde foi escrita (o método alerta, onde this é a Pessoa).

As classes também podem ser anónimas, como expressões: let Pet = class { constructor(nome) { this.nome = nome; } }; e depois new Pet("Bola"). Só existem através da variável que as guarda.

Tema 6 — JavaScript: DOM, CSSOM e eventos

Reflexão

A reflexão representa a formatação da página como objetos, que o código pode ler e alterar. Há três modelos:

  • widgets: o mais antigo, só para formulários; evitar;
  • CSSOM (CSS Object Model): o estilo de cada elemento;
  • DOM (Document Object Model): a estrutura inteira do documento.

Widgets. Cada campo de formulário (input, select, textarea) é um objeto com name e value. Num callback, this é o elemento corrente; this.form é o seu formulário, que tem uma propriedade por nome de campo:

<form>
  <input name=a size=2 value=1> +
  <input name=b size=2 value=1>
  <input type=button value="=" onclick="
     this.form.c.value =
       parseInt(this.form.a.value) +
       parseInt(this.form.b.value);">
  <input name=c size=2>
</form>

Ao clicar em “=”: this é o botão, this.form.a e this.form.b são os campos pelo name; os valores (strings) passam a inteiros com parseInt e somam-se, e o resultado vai para this.form.c.value (mostrado como texto).

CSSOM. Todo o elemento tem a propriedade style, um objeto com o estilo em linha do elemento, que se pode inspecionar e alterar: element.style.background = "orange". Os nomes simples são iguais aos do CSS (color, width); os nomes com hífen passam a lowerCamelCase (font-size → fontSize, border-style → borderStyle), porque style.font-size seria lido como a subtração style.font - size†.

<select onchange="this.form.style.color = this.value;">
  <option></option> <option>orange</option> <option>DarkBlue</option>
</select>
<select onchange="this.form.style.fontSize = this.value;">
  <option>24pt</option> <option>36pt</option> <option>12pt</option>
</select>

Ao escolher “orange”, this é o <select> e this.value é "orange": o formulário fica com style.color = "orange" e o navegador repinta-o. O segundo <select> muda style.fontSize (o font-size do CSS).

A árvore DOM

O DOM reflete o documento inteiro como uma árvore de objetos, com uma API para a consultar e alterar. Serve também para XML (o HTML só acrescenta algumas propriedades). Tipos:

  • Document: o documento como um todo;
  • Node: o tipo mais geral de nó;
  • Element: nós criados por pares de anotações;
  • Text: nós de texto pendurados nos elementos;
  • NodeList: uma coleção de nós (não é um nó).

Cada nó tem um progenitor (exceto a raiz). Element e Text são especializações de Node (herdam as suas propriedades e métodos). Os espaços em branco entre anotações (mudanças de linha, indentação) também dão nós de texto.

<html>
  <head> <title>Uma página</title> </head>
  <body>
    <h1>Uma página</h1>
    <p>Uma linha</p>
    <p>Ainda <b>outra</b> linha</p>
  </body>
</html>

html tem os filhos head e body; head tem title, com o texto "Uma página"; body tem h1 (texto "Uma página"), um p (texto "Uma linha") e outro p com três filhos: o texto "Ainda ", o elemento b (texto "outra") e o texto " linha".

A variável global document dá acesso à árvore, para obter elementos e criar nós.

  • querySelector(s): o primeiro elemento que corresponde ao seletor CSS s; querySelectorAll(s): todos, numa NodeList. Também existem nos elementos, para procurar só lá dentro.
  • document.createElement(tag) cria um Element; document.createTextNode(texto) cria um Text. Os nós criados ficam soltos: só aparecem depois de ligados à árvore (appendChild, …).

  3. insertBefore(nl, next) põe o "\n" entre a caixa nova e next.

Uma NodeList agrega nós: os filhos de um elemento, ou o resultado de uma pesquisa (getElementsByTagName, querySelectorAll). Tem length e item(indice) (a partir de 0).

let conta = 0;
function contar() {
    const base = document.getElementById("base");
    const lista = base.getElementsByTagName("div");
    conta++;
    for (let i = 0; i < lista.length; i++)
        lista.item(i).innerText = conta;
}

Eventos

A programação tradicional é proativa: começa numa função (main), que invoca outras e recebe o controlo de volta. A programação por eventos é reativa: um troço de código só corre em resposta a um evento, representado por um objeto passado à função registada para esse tipo de evento nessa origem.

Um registo tem três partes: o elemento, o tipo de evento e o callback. Os tipos (janela, teclado, rato, widgets, …) dão origem a atributos HTML e propriedades DOM com o prefixo on, e ao primeiro argumento de addEventListener.

Modo 1: atributo HTML. O atributo on + evento (onclick) tem como valor uma string de código. Qualquer elemento os pode ter, e this é o elemento.

<div style="..." onclick="with(this.style) {
     let tmp = color;
     color = background;
     background = tmp;
   }"> Don't click me! </div>

Modo 2: propriedade do elemento. Separa o HTML do JavaScript: uma função (normalmente anónima) vai para a propriedade com o mesmo nome do atributo. O elemento obtém-se com getElementById, e por isso só depois de a janela carregar (window.onload).

window.onload = function() {
   const button = document.getElementById("button");
   button.onclick = function() {
      const tmp = button.style.color;
      button.style.color = button.style.background;
      button.style.background = tmp;
   };
};

Nos modos 1 e 2, um novo callback substitui o anterior†: só há um por evento e elemento.

Modo 3: addEventListener (DOM Level 2). Permite vários callbacks no mesmo elemento e evento. Argumentos: o nome do evento sem on ("click"), o callback, e a fase (true = capturing, false = bubbling).

window.addEventListener("load", function() {
   const button = document.getElementById("button");
   button.addEventListener("click", function() {
      const tmp = button.style.color;
      button.style.color = button.style.background;
      button.style.background = tmp;
   }, false);
}, false);

Fases. Os elementos sobrepõem-se (cada um contém os descendentes), por isso o evento é entregue a todos os elementos no caminho entre a raiz e o alvo. Havia duas convenções: capturing, do mais externo para o mais interno (Netscape), e bubbling, do mais interno para o mais externo (Microsoft). O DOM combina-as: a captura desce da raiz ao alvo, o alvo processa, e o bubbling sobe de volta. O terceiro argumento de addEventListener escolhe a fase do callback; o habitual é false (também a omissão†); a captura serve para intercetar um evento antes de chegar ao alvo.

O objeto Event, passado ao callback, tem informação sobre o evento e controla a propagação. Propriedades (exemplos): bubble (está na fase de bubbling), cancelBubble (cancela o bubbling). Métodos: preventDefault() (cancela a ação por omissão, se possível: navegar num link, começar uma seleção de texto) e stopPropagation() (para a propagação). Há classes especializadas por categoria de evento.

Janela. O evento load (a página e os recursos acabaram de carregar) é da janela: window.onload = ... ou window.addEventListener("load", ...). Espera-se por ele para obter elementos com getElementById.

Trabalho prático — 1.ª entrega (Alquerque)

1. Regras do Alquerque

(Há variantes do jogo — no trabalho contam só estas.)

Tabuleiro, peças e posição inicial

  • Grelha de 5 × 5 = 25 posições (as interseções das linhas). Os caminhos válidos são as linhas horizontais, verticais e diagonais desenhadas.
  • Nem todas as posições têm diagonais: só as posições com linha % 2 == coluna % 2 (os cantos, o centro, …). Nas outras só se anda na horizontal e na vertical.
  • Cada jogador tem 12 peças da sua cor (ex.: azul e vermelho). As duas filas do seu lado são suas; na fila do meio fica com as 2 posições à sua direita; o centro começa vazio (é a única posição vazia).

Convenção usada neste documento (é a mesma do código do site, Position(row, column)): linha 0 em cima, coluna 0 à esquerda; as azuis começam em baixo e avançam para cima, as vermelhas o contrário.

Movimento simples (sem captura)

  • Os jogadores alternam; em cada vez fazem um movimento ou uma captura.
  • Um movimento leva uma peça para uma posição adjacente e vazia, desde que haja uma linha a ligá-las e a peça não recue em direção à sua fila inicial (para o lado pode).
  • Na última fila (a do adversário) a peça só se pode mover na horizontal.

Capturar

  • Captura-se saltando por cima de uma peça adversária adjacente para a posição vazia logo a seguir, na mesma linha. A peça saltada sai do tabuleiro.
  • Ao contrário do movimento, a captura pode ser para trás (e uma peça na última fila pode capturar para o lado ou para trás).
  • Se houver captura possível, é obrigatório capturar — quem não capturar arrisca o sopro .

Capturas múltiplas

  • Depois de capturar, a mesma peça pode continuar a capturar no mesmo turno, mudando de direção em cada salto, mas sem passar duas vezes pela mesma posição nem saltar duas vezes a mesma peça.
  • Se houver vários percursos, escolhe-se qualquer um (não tem de ser o que captura mais). Mas no percurso escolhido é obrigatório continuar a capturar enquanto der.

Regra do sopro (penalização)

  • Se o adversário podia ter capturado e não o fez — moveu essa ou outra peça, ou fez só uma captura simples quando podia fazer uma múltipla — tu podes “soprar” (retirar definitivamente) uma peça dele: a que devia ter capturado.
  • O sopro é opcional e faz-se no início da tua jogada, antes de mover ou capturar. Mesmo que várias peças pudessem ter capturado, só se sopra uma.

Fim do jogo

  • Perde quem, na sua vez, não tem peças ou não tem nenhuma jogada válida (nem movimento nem captura).
  • Empate por acordo mútuo, por exemplo quando já não pode haver capturas (as peças já se cruzaram e não podem recuar) ou quando já não há capturas há muitas jogadas. Daí o comando “propor/aceitar empate”.

2. 1ª entrega — o cliente (só contra o computador)

Requisitos técnicos

  • Aplicação de página única (single-page application): tudo numa só página index.html, sem carregar outras páginas HTML.
  • CSS em um ou mais ficheiros .css próprios; JavaScript num ficheiro .js próprio.
  • HTML e CSS têm de passar no validador do W3C; erros de CSS são penalizados. Se o validador rejeitar uma feature de CSS, não a uses.
  • Sem frameworks de JS nem de CSS.

As áreas da página

Não têm de estar todas visíveis ao mesmo tempo; algumas podem ser painéis que se sobrepõem temporariamente aos outros.

Área O que tem de fazer
Logotipo Nome do jogo em destaque (“Alquerque” ou um nome vosso), em texto formatado ou imagem.
Configuração Escolher: contra o computador ou contra outro jogador (na 1ª entrega só se implementa contra o computador); quem joga primeiro; nível da IA.
Comandos Ver instruções; iniciar jogo com a configuração atual; propor/aceitar empate; desistir (vitória para o adversário); ver classificações.
Identificação Login (identificador + senha) e, depois de autenticado, mostrar o nome e permitir sair. Na 1ª entrega não autentica nada, mas a área tem de existir e estar formatada.
Tabuleiro A área principal (ver abaixo).
Instruções As regras do jogo (§1) e como jogar nesta aplicação. Pode ser um painel sobreposto, com um comando para abrir e outro para fechar.
Classificações Tabela com os melhores resultados; na 1ª entrega, só dos jogos contra a IA. O conteúdo é livre desde que faça sentido (ex.: vitórias e derrotas por nível). Também pode ser um painel sobreposto.
Mensagens É a tua vez; jogada inválida; fim do jogo e quem ganhou; o adversário propôs empate; desististe e perdeste.

Tabuleiro

  1. Fase 1: escrever o tabuleiro à mão em HTML (contentores para as linhas e as peças), com o posicionamento e o aspeto em CSS.
  2. Fase 2: gerar o tabuleiro a partir de JavaScript, através da DOM e da sintaxe JS do CSS (elem.style..., classList).
  3. Começa pela estrutura de dados que representa o tabuleiro (ex.: uma matriz 5 × 5 com 'Blue', 'Red' ou null, como no código do site). Os métodos que desenham o tabuleiro e tratam os cliques trabalham sobre esses dados; na 2ª entrega serão estes os dados trocados com o servidor.
  4. É valorizada uma abordagem orientada a objetos (ex.: classes Board, Position, Game).

Modos de interação. O mesmo clique faz coisas diferentes consoante o momento, por isso é preciso guardar o estado da interação em variáveis:

Clique Significado
1.º clique numa peça do adversário essa peça é soprada (se o sopro for possível)
1.º clique numa peça tua escolhes a peça a jogar
clique seguinte numa posição adjacente válida a peça move-se logo
clique seguinte numa posição com uma peça adversária pelo meio é uma captura; como pode ser múltipla, continuas a clicar nos destinos e voltas a clicar para terminar a jogada

O utilizador tem de saber sempre em que modo está, através do cursor e/ou de mensagens.

IA (obrigatória)

As jogadas do computador são calculadas no cliente. Podes usar uma destas abordagens ou combiná-las:

  • aleatória: gerar todas as jogadas válidas e escolher uma ao calhas;
  • gulosa: preferir as jogadas que capturam;
  • níveis de dificuldade: em cada jogada sortear qual das duas usar, com mais probabilidade de usar a gulosa nos níveis mais altos;
  • opcional: Minimax, com o nível a determinar a profundidade da procura.

Repara que, para qualquer uma delas, precisas de uma função que gera todas as jogadas válidas de um jogador, incluindo as capturas múltiplas, a obrigação de capturar e o sopro. Essa função é também a que valida as jogadas do humano e deteta o fim do jogo, por isso é o núcleo do trabalho.
